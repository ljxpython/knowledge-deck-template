# Making Better Technical Decisions

Audience: practitioners choosing an implementation path under changing constraints.

## Start with the decision, not the tool

Strong decisions make the constraint visible before comparing options.

## Compare by consequence

Trade speed, reversibility, and operational cost rather than feature checklists.

## Work in a deliberate sequence

Frame the question, gather evidence, decide, and record what would change the decision.

## Keep the decision alive

Revisit the decision when assumptions or constraints change.
